# D435 ↔ PX4 IMU calibration (Kalibr) and OpenVINS VIO

Automates bag recording and [Kalibr camera-IMU calibration](https://github.com/ethz-asl/kalibr/wiki/camera-imu-calibration)
on the Raspberry Pi 5 (Ubuntu 24.04, ROS 2 Jazzy), then runs OpenVINS on the result and feeds it to PX4 EKF2.
The ROS 2 packages it runs (px4_msgs, OpenVINS, nap_px4_bridge) live in [`../vio_ws`](../vio_ws).

## Setup (once)

```bash
sudo apt install ros-jazzy-realsense2-camera ros-jazzy-cv-bridge ros-jazzy-image-transport \
    ros-jazzy-tf2-geometry-msgs libceres-dev libopencv-contrib-dev
cd ../vio_ws && source /opt/ros/jazzy/setup.bash
MAKEFLAGS=-j3 colcon build --parallel-workers 2 --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3
#   ~/.local/bin/python3.11 otherwise wins CMake's Python lookup and lacks empy (px4_msgs fails: No module named 'em').
#   -j3 / 2 workers keep the OpenVINS compile inside the Pi 5's 8 GB.
```

MicroXRCEAgent must be on `PATH` (built from [Micro-XRCE-DDS-Agent](https://github.com/eProsima/Micro-XRCE-DDS-Agent)).
Optional, for `tools/start_foxglove_bridge.sh`: `sudo apt install ros-jazzy-foxglove-bridge`.

PX4 side (v1.16.0, Pixhawk 6C; `vio_ws/src/px4_msgs` must match the firmware release):
`UXRCE_DDS_CFG=102` (TELEM2), `SER_TEL2_BAUD=921600`, `SYS_USB_AUTO=0`. With USB MAVLink auto-start
on, the FC's CPU contention kept dropping the uXRCE-DDS session.

## Why it is set up this way

| Fact about this system | Consequence |
|---|---|
| Camera is a plain **D435** (no accel/gyro; `rs-enumerate-devices` shows no motion streams) | The IMU is the **Pixhawk 6C's**, via `MicroXRCEAgent` → `/fmu/out/sensor_combined`. Camera and FC **must be rigidly mounted** together. |
| PX4 stamps IMU with *time since FC boot*; RealSense stamps images with *host time* | `tools/px4_imu_restamp.py` republishes the IMU as `/calib/imu` on the host clock (min-latency offset). The `nap_px4_bridge` `/d435i/imu` is **not** usable for Kalibr as-is. |
| Kalibr is ROS 1 only; 24.04 has no ROS 1 | Kalibr runs in Docker (`ros:noetic`, arm64). ROS 2 bags are converted with [`rosbags`](https://pypi.org/project/rosbags/) in a local `.venv`. Nothing is installed system-wide. |
| IR projector is visible in infra1/infra2 | Emitter is disabled for recordings (`config/realsense_calib.yaml`). |
| PX4 `sensor_combined` arrives at ~100 Hz | Works with Kalibr, but ≥200 Hz is better. Consider raising the rate in PX4's uXRCE-DDS topic config. |

## Workflow

```bash
./00_check_env.sh                 # read-only check of camera, FC link, docker, disk
./01_build_kalibr.sh              # once: rosbags venv + Kalibr image (~1-2 h on Pi 5) + target PDF
#   print config/aprilgrid.pdf at 100 %, mount on a rigid board, measure tag -> fix tagSize

./02_start_sensors.sh             # terminal 1: agent + D435 + IMU re-stamper (Ctrl+C stops all)
./03_record.sh cam                # terminal 2: stereo intrinsics bag (slow motions)
./03_record.sh imu                # terminal 2: camera-IMU bag (excite all 6 axes)

./05_calib_cameras.sh cam_<stamp>               # converts the bag and writes the camchain
./06_calib_cam_imu.sh imu_<stamp> cam_<stamp>   # T_cam_imu + time offset
./08_install_openvins_config.sh [imu_<stamp>]   # results -> OpenVINS config (default: newest)

./07_start_vio.sh                 # fly: agent -> D435 -> IMU re-stamper -> OpenVINS -> PX4 bridge, one tmux window each
./07_start_vio.sh stop            # stop everything (also: ./07_start_vio.sh status)
tools/start_foxglove_bridge.sh    # optional: read-only Foxglove view from a laptop (ws://<pi-ip>:8765)
```

## Where things live

| Path | Contents |
|---|---|
| `bags/` | recorded ROS 2 bags + converted ROS 1 `.bag` only (gitignored) |
| `results/cam_<stamp>/` | stereo calibration: `-camchain.yaml`, `-results-cam.txt` |
| `results/imu_<stamp>/` | camera-IMU calibration: `-camchain-imucam.yaml`, `-imu.yaml`, `-results-imucam.txt`, `imu_input.yaml` (the report PDF stays local, gitignored) |
| `../vio_ws/src/open_vins/config/d435_px4/` | what OpenVINS runs with: hand-tuned `estimator_config.yaml` + `kalibr_*_chain.yaml` generated by step 08 (`CALIBRATION_SOURCE` names the result used) |

OpenVINS reads that config from `src/` via `config_path`, so recalibrating needs no colcon rebuild.
OpenVINS uses `/calib/imu` (the re-stamped PX4 IMU) — the same topic and clock the calibration was done on.

Optional: `./03_record.sh static` records 3 h of the still FC. Run Allan variance on it (e.g.
`allan_variance_ros` inside the Kalibr container) and replace the noise values in `config/imu_px4.yaml`.

## Before trusting the result

- The camera calibration reprojection error should be < ~0.3 px. Distortion should be ≈ 0, because D435 Y8 infra is rectified on the ASIC.
- `timeshift_cam_imu` should be a few ms. A value near ±0.1 s means it hit the search limit, so check the re-stamper log.
- The translation in `T_cam_imu` should match a tape-measured distance between the D435 and the FC within about 1 cm.
- The IMU frame is PX4 **FRD**, the same frame `nap_px4_bridge` publishes to OpenVINS.

## Easier (less accurate) alternative: skip Kalibr

OpenVINS can estimate the camera-IMU extrinsics and time offset online
(`calib_cam_extrinsics: true`, `calib_cam_timeoffset: true`). To use it, start from the D435 factory
intrinsics (`/d435i/infra1/camera_info`) and a tape-measured `T_imu_cam`. This avoids the Docker
build and the target. However, the estimate only converges with good motion excitation and isn't
repeatable. Use it for bench tests, and use Kalibr before flying.
